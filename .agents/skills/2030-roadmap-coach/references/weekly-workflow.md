# Weekly Learning Workflow

## Standard target: 14 hours

- Mon: theory/primary resource and questions — 2 h
- Tue: focused lab or implementation — 2 h
- Wed: continue implementation plus Go DSA — 2 h
- Thu: tests, failure cases, debugging or profiling — 2 h
- Fri: system design, review notes or paper summary — 1.5 h
- Sat: integrate the weekly deliverable — 3 h
- Sun: benchmark/document/review and next-week plan — 1.5 h

Use a 9-hour fallback in busy work weeks: retain one theory session, one implementation session, tests/experiment, interview practice and a short review. Stretch the roadmap rather than skipping verification.

## Every week's plan

1. Pick one primary topic and one concrete question.
2. Choose a bounded section of a canonical resource.
3. Define a deliverable and acceptance criteria.
4. State assumptions, invariant(s), likely failure cases and expected signals.
5. Implement a small slice; ask an AI assistant for help only with scoped tasks.
6. Run relevant tests and experiments; preserve output or results.
7. Write a brief note with design trade-offs, evidence, caveats and questions.
8. Update the weekly log and choose the next action.

## Weekly log template

```markdown
## Week YYYY-WW — [topic]
- Roadmap phase/week:
- Objective:
- Primary resource:
- Deliverable:
- Work completed:
- Tests/experiments run:
- Evidence/results:
- What I can now explain:
- Open gaps:
- Interview practice:
- Next action:
```

## Buffer weeks
Finish incomplete deliverables, repair misconceptions, rerun flaky experiments, review the roadmap against target roles and perform a mock interview. Do not use buffer weeks to add a large new framework.
