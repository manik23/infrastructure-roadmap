# Continuous and Follow-up Cheatsheet

**Source:** [Roadmap continuous tracks and follow-ups](../../ROADMAP_2030_REVISED.md#part-ii--continuous-tracks-run-alongside-the-core)

## Continuous practice

- DSA: explain complexity and edge cases; re-solve missed patterns tomorrow, next week, and next month.
- LLD: interfaces, state transitions, cancellation, errors, testing seams, and resource bounds.
- HLD: requirements/SLOs → estimates → API/data → failure semantics → bottlenecks → security/cost.
- AI output: specify first; test cancellation, duplicates, timeouts, partial failures, and exhaustion.

## Follow-up guardrails

- Rust is planned after core control-plane progress, not a substitute for Go fundamentals.
- Choose one specialty based on target role and project evidence; do not start all tracks together.
- For any performance/security claim, preserve workload, environment, baseline, and limitations.
